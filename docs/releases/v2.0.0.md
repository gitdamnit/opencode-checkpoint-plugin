## Relationship between the tested commit and the release commit

The release commit is `65bf698` plus release preparation only: the version
metadata (`package.json`, `package-lock.json`, `PLUGIN_VERSION` and the rebuilt
`dist/`), the release documentation in this directory and in `CHANGELOG.md` /
`README.md` / `docs/`, and the publish workflow. No functional source change was
made after the tested commit, so the 145/145 result above is the result for this
release's code. The 145/145 figure must not be re-attributed to a newer commit.

If a functional change is ever required for v2.0.0, the freeze is void and the
lab must be re-run against the new commit before publishing.

## Known limitations carried into 2.0.0

1. `node:sqlite` may still produce an experimental API warning under plain Node;
   it is unflagged from Node 22.13.0 / 23.4.0, and Bun (the runtime OpenCode
   uses) does not warn.
2. The plugin requires OpenCode V2. V1 is intentionally not supported; the
   `1.0.1` line remains installable for V1 users.
3. SQLite checkpoints belong to their respective sessions; they are never shared
   implicitly between sessions.
4. Legacy migration is deliberate and never automatically injects old data into
   an active session; adoption is explicit via `checkpoint_migrate`.
5. A compaction after clearing checkpoint state can create a non-injected
   synthesized placeholder.
6. The prompt hook is not an exactly-once event ledger.
7. Project identity and directory mapping have documented edge cases.

The full list is in [README.md](../../README.md#known-limitations).
